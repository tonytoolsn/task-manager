# 範本包安裝說明

這包是**正式團隊的完整範本清單**。
一人專案不需要全部使用 —— 下表標明了現在該裝哪些。

---

## 檔案清單與優先級

| 檔案 | 放到哪 | 一人專案 | 說明 |
|---|---|---|---|
| `README.md` | 根目錄 | ✅ **現在裝** | repo 首頁,最重要的檔案 |
| `.github/ISSUE_TEMPLATE/config.yml` | 照路徑 | ✅ **現在裝** | 禁止開空白 Issue |
| `.github/ISSUE_TEMPLATE/*.yml` | 照路徑 | ✅ **現在裝** | YAML 表單版範本 |

## YAML 版 vs Markdown 版

本包提供兩種 Issue 範本,**選一種使用,不要同時放**。

```
.github/ISSUE_TEMPLATE/        ← YAML 版（建議)
.github/ISSUE_TEMPLATE_MD/     ← Markdown 版（備用)
```

### 差異

| | Markdown（`.md`) | YAML（`.yml`) |
|---|---|---|
| 呈現 | 一個文字框,內含預填內容 | 真正的表單欄位 |
| 必填 | ❌ 無法強制 | ✅ 沒填不能送出 |
| 下拉選單 | ❌ | ✅ |
| 自動加標籤 | ✅ | ✅ |
| 自動加標題前綴 | ✅ | ✅ |
| 事後編輯 | 自由 | 送出後變成一般 markdown,可自由編輯 |

### 建議用 YAML

**理由:它把紀律變成系統強制。**

Markdown 範本可以整段刪掉 —— 趕時間時你一定會這麼做,
然後那張票三週後你就看不懂了。
YAML 表單的必填欄位擋得住這件事。

### 什麼時候該用 Markdown 版

- 你的票格式還在調整,YAML 改起來比較囉唆
- 需要在範本裡放大量說明文字或程式碼區塊
- 團隊成員抱怨表單太拘束

### 安裝方式

**用 YAML 版**(建議):

```
把 .github/ISSUE_TEMPLATE/ 整個資料夾放進專案
刪掉 .github/ISSUE_TEMPLATE_MD/
```

**用 Markdown 版**:

```
把 ISSUE_TEMPLATE_MD 改名為 ISSUE_TEMPLATE
把 config.yml 從原本的 ISSUE_TEMPLATE 移進去（config.yml 兩種都適用)
```

## 四種 Issue 範本

| 範本 | 什麼時候用 | 自動加的標籤 |
|---|---|---|
| 功能 | 新增功能 | `type:feat` |
| Bug | 有東西壞了 | `type:fix` |
| 技術債 | 重構、補測試、清理程式碼 | `type:refactor` |
| 研究 | 純研究,產出是「知道怎麼做」 | `type:spike` |

### 為什麼「研究」需要獨立範本

Spike 沒有功能產出,但它是真實的工作。

**它的範本有兩個特殊欄位:**

- **時間盒** —— 超過就停止,用當下已知的資訊做決定。
  沒有時間盒的研究會無限進行下去。
- **結論** —— 研究完回來填,並同步寫進 `learning-log.md`。

有了這張票,你就不會覺得「查了半天資料」的那段時間是浪費掉的。

## config.yml 的關鍵設定

```yaml
blank_issues_enabled: false
```

**禁止開空白 Issue,強迫每張票都走範本。**

不然趕時間時你會點「Open a blank issue」隨手寫兩行,
那張票三週後就變成謎題。

`contact_links` 裡的網址記得改成你自己的 repo 路徑。

## dependabot.yml 說明

每週一自動檢查 Composer 和 npm 套件是否有更新,有的話開 PR。

```yaml
open-pull-requests-limit: 3
```

**這行是必要的。** 不設限制的話,第一次啟用可能一次開二十個 PR,
直接淹沒你的看板。

### 對一人專案的實際價值

你會定期收到「有套件可以更新」的 PR ——
這是練習「review 一個我沒寫的 PR」的好機會,
也是真實工作裡最常見的日常任務之一。

**什麼時候啟用**:等 `task-api/composer.json` 和
`task-web/package.json` 真的存在之後。現在放上去它會找不到目錄。

## CHANGELOG.md 的撰寫紀律

**寫給「使用者」看,不是給工程師看。**

```
✅ 可以依專案篩選任務
❌ 新增 TaskController@index 的 project_id 參數
```

開發中的變更先放 `[Unreleased]`,發版時才移到新版本區塊下。

檔案裡有完整的撰寫規則(在 HTML 註解中),寫的時候可以參考。

## 安裝後的檢查

```
□ README.md 的技術棧、連結路徑都正確
□ config.yml 的 contact_links 網址改成自己的 repo
□ 只保留一種 Issue 範本格式（YAML 或 Markdown)
□ 開一張測試 Issue,確認範本選單有出現四個選項
□ 確認無法開空白 Issue
□ 測試完把那張測試 Issue 關掉
```

> ⚠️ 這些檔案都要**透過 PR 進 main**(branch protection)。
> 記得開分支:`git checkout -b docs/12-add-templates`
